# Section model — POPULOS neutral template

The approved template defines the canonical order below. A section may be shortened, have rows removed, or explicitly state a pending dependency, but it must not silently acquire invented content.

## Canonical blocks

1. Cover.
2. About POPULOS, manufacturer, partnership, and qualification evidence.
3. Executive summary and project objectives.
4. Solution description organized into evidence-backed technological fronts.
5. Quantities, locations, and dimensioning status.
6. Current-environment assessment and migration approach.
7. POPULOS implementation services and methodology.
8. Scope boundaries, knowledge transfer, tests, and exclusions.
9. Assumptions, people requirements, and restrictions.
10. Macro schedule.
11. Acceptance criteria.
12. Technical warranty and service conditions.
13. Roles and responsibilities, confidentiality, and legal footer.

## Conditional blocks

- Company profile: include only when requested or useful for a formal bid.
- Current-state architecture: include when the discovery provides reliable topology.
- Product detail: one concise module per recommended product; avoid brochure copy.
- Options: include optional products outside the primary solution with explicit triggers.
- Migration or rollout: include when cutover, waves, rollback, or coexistence matters.
- Support and operations: include only when support is in scope or operational ownership needs definition.
- SLA: preserve the fixed table from the approved template as an institutional POPULOS commitment; do not append a hedge that postpones its definition.
- Warranty: populate only after an explicit opportunity-specific POPULOS decision. An unresolved warranty placeholder blocks emission.
- License supply: state whether POPULOS resells the Akamai licenses or the client purchases them directly. An unresolved supply model blocks emission.
- Critical-event readiness: include when a named peak or seasonal event is material to the opportunity.
- Compliance and privacy: include when requirements or regulated data justify it.
- Confidentiality: include when required by the proposal process.
- Signature: include only when the proposal is intended for formal acceptance.

## Block rules

- The block order follows the approved source template.
- A block can contain paragraphs, bullets, a comparison matrix, a responsibility matrix, or a diagram specification.
- Avoid repeating the same product description in the executive summary, architecture, and product module.
- The document manifest is authoritative for rendering. Unlisted blocks and assets are not emitted.
